# Conflict-free team handovers land without a base re-merge

In a `team` run the lead checks its own task branch and hands it over without merging the current base
first. The integrator probes for conflicts and lands a conflict-free handover even when the base has moved:
the fast shared checks run on the merged state, an expensive check only where the base movement touches its
path areas, otherwise once at the end of the run. A conflict still goes back to the lead.

## Project

- `.qatlas-project/TESTING.md` or other native test instructions: if they state that the lead merges the
  base before a handover and checks that state, that a moved base goes back as `rework` (`rework base
  moved`), or that the integrator lands nothing else until such a handover returns, propose removing those
  statements. They make every landing bounce the other leads' handovers and serialize the run. Keep any
  declared tiers and path areas of expensive checks; the integrator uses them for the delta checks.
- Nothing to do if no such statement exists.
