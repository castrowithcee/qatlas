# AGENTS.md is the entry, reserved files replace folders

The knowledge space has no README any more. `AGENTS.md` names the project's purpose and rules and points
with read conditions into `.qatlas-project/`, whose own state lives in the reserved files `CONVENTIONS.md`,
`ARCHITECTURE.md`, `TESTING.md` and `CONTRIBUTING.md` and the fixed folders. Both arise with their first
entry; nothing is created empty. The mapping follows the migration block of `qatlas-core update`.

## Project

- `.qatlas-project/README.md`: move its read conditions into a section `Project knowledge` of `AGENTS.md`,
  one line per reserved file or folder entry that exists, and its project overview into `Purpose`; then
  remove the file. Until it is removed, the session start still injects it.
- `policies/`, `policies/conventions/`, `decisions/` and similar folders: work each statement into the
  reserved file it concerns, with its reason, or into `AGENTS.md` if it must hold in every session. A file
  that would push a reserved file over 300 lines goes into the folder of the same name in lower case, and the
  reserved file points to it. Remove the emptied folders.
- A test strategy, acceptance profile or pull request rule inside `AGENTS.md`: move it to `TESTING.md` or
  `CONTRIBUTING.md` and leave the read condition in `AGENTS.md`.
- Empty folders and `.gitkeep` placeholders: remove them; a folder arises with its first entry.
- `backlog/IDEAS.md` without ideas, or with an external planning system: remove it.
- `memory/`: keep it. Only a project that wants no repo memory sets `memory.enable: false` in
  `.qatlas/plugins/config.yaml`; then the index is not injected and no memory files arise.

## Library

- `~/qatlas/AGENTS.qatlas.md`: the shipped seed now holds only precedence and the library pointer. Keep your
  own content; a section on safe commands is yours to keep or drop.
