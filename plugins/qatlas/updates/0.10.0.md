# Abschlussweg externer Backlog-Bindungen prüfen

- Prüfe nur, wenn `.qatlas-project/backlog/BACKLOG.md` ein externes Planungssystem bindet. Bei lokalem
  Backlog ist nichts anzupassen.
- Fehlt der Bindung eine Angabe, wie ein erledigter, verworfener oder doppelter Arbeitseintrag im System
  geschlossen wird, schlage eine knappe Zeile `Abschluss` vor. Bei GitHub lautet sie sinngemäß: Erledigt
  wird mit `gh issue close <nummer> --reason completed` geschlossen und im selben Schritt auf `Done`
  gesetzt, verworfene Arbeit mit `--reason "not planned"`; maßgeblich ist der Issue-Zustand.
- Grund: Ohne diese Angabe setzen Run und Review nur den Status. Das Issue bleibt offen, obwohl die Arbeit
  abgeschlossen ist.
- Prüfe lesend, ob Arbeitseinträge auf dem Abschlussstatus noch offen oder geschlossene Einträge auf einem
  anderen Status stehen. Nenne Anzahl und ein Beispiel und gleiche sie erst nach Bestätigung ab.
- Enthält die Bindung bereits einen gleichwertigen Abschlussweg, ist nichts anzupassen. Vorhandene
  Formulierungen bleiben primär.
