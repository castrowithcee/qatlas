# Role configuration is now team.yaml

The device-wide file `~/.qatlas/plugins/orchestra.yaml` is now called `~/.qatlas/plugins/team.yaml` and
carries `format: 2`. `orchestrator` became `lead`, `supervisor` and `integrator` are new and take the same
value as `orchestrator` had, `workers` became `worker`; `profiles` and `test-slots` are unchanged. The session
start takes the old file over automatically: it makes a backup first, leaves the old file in place and names
it. Comments of the old file are not carried over; the new file gets a short comment header, and the
commented template lives at `store/config/team.example.yaml`.

- If `team.yaml` already exists, nothing is written. An invalid old file blocks the takeover and is reported.
- Nothing changes in this repo itself, and no project file is touched by this update.
- Once the user has checked the new file, offer to delete the old one; do not delete it yourself.

# The parallel mode is now qatlas team

The parallel mode `qatlas sentinel` is now called `qatlas team`, and the flag `--orchestras <n>` is now
`--leads <n>`. The roles are supervisor (formerly sentinel), lead (formerly orchestrator) and worker. The
control script, the pane option, the tmux socket and session name and the local run state moved with the
mode; behavior is otherwise unchanged.

- End running sentinel runs before the update; a run started under the old name cannot be continued.
- Old run state under `.qatlas/local/sentinel/` is not taken over and can be deleted. Offer that; do not
  delete it yourself.
- If project instructions or memory of this repo mention `qatlas sentinel`, "sentinel" or "orchestrator",
  check them against `qatlas team`, supervisor and lead and propose the concrete change to the user.

# Team leads push and open pull requests

With integration via pull requests, each `qatlas team` lead now pushes its own task branch, opens the pull
request and fixes a red CI itself; it hands over the open pull request with green CI, or without CI with a
green complete local test, and no longer has to merge the current base before a handover. A dedicated
integrator session started by the supervisor merges, closes tasks and sets `done`; the supervisor integrates
nothing.

- If project instructions allow push, pull request creation or merge to only one role, check them against this
  (merge: the integrator) and propose the concrete change to the user.
